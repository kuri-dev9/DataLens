# SKILL BOOK 저술 가이드

DataLens는 도메인 지식을 코드에 담지 않는다. 지식은 **책**으로 꽂고, DataLens는 책
내용을 모르는 **책장**으로서 보관·색인·검색·주입만 한다.

형식 계약의 정본은 **ADR-037**(`docs/ADR.md`)이다. 이 문서는 그 계약을 다시 쓰지 않고
**어떻게 쓰는지**만 보여준다. 계약과 어긋나 보이면 ADR이 맞다.

`example-book/`은 복사해서 시작할 수 있는 견본이며, 그 자체로 유효한 책이다
(카드 13장 — 서술 3장, 표 행 10장).

## 핵심 — 청킹은 저술 시점에 끝난다

일반 RAG는 문서를 기계적으로 잘라(고정 크기) 전부 임베딩한다. 그 방식을 실제 지식
문서에 적용해 비교한 결과다.

| | 청크 수 | 평균 크기 | 경계 파괴 | 지식 1건당 주입량 |
|---|---|---|---|---|
| 고정 500자 청킹 | 263 | 488자 | 헤더 잃은 표 조각 27개 | 500자 |
| 저술 시점 청킹 | 1,425 | 75자 | 0 | 28~158자 |

고정 청킹의 500자에는 무관한 항목이 5~6개 섞여 모델이 "어느 설명이 질문 대상인지"를
흐리게 읽고, 표 중간이 끊겨 컬럼 의미를 잃은 조각이 생긴다.

**그래서 책을 쓸 때 이미 쪼개진 형태로 쓴다.** 표의 행 하나가 지식 하나이고, 서술
장의 절 하나가 지식 하나다. 파일이 장 단위인 것은 사람이 읽기 위한 포장일 뿐이다.

## 장마다 경계를 선언한다

책장은 의미를 판단하지 않는다. 장이 *레코드 목록*인지 *해석 서술*인지는 저술자만 안다.

```yaml
---
card_unit: row       # 표 1행 = 지식 1개
card_key: 지표        #   카드 제목이 될 컬럼 이름
---
```

```yaml
---
card_unit: section   # ## 절 1개 = 지식 1개
---
```

**어느 쪽인지 고르는 기준**은 "한 줄만 떼어내도 뜻이 서는가"다. 지표 정의·코드값·필드
설명처럼 행 단위로 완결되면 `row`, 조합해서 읽어야 하는 규칙·원칙·사례면 `section`이다.
한 장에 둘을 섞지 말고 장을 나눈다 — 서술 장 안의 표는 그 절의 일부로 함께 색인된다.

선언이 없으면 절 단위로 색인되지만, 큰 청크는 검색 랭킹에서 불리하고 주입 예산을 많이
먹어 자연히 밀린다. 등록 보고가 "이 장에 `card_unit: row`를 선언하면 카드 N장으로
쪼개진다"를 알려준다.

## 표를 쓸 때

**`card_key` 컬럼이 없는 표는 카드가 되지 않는다.** 건수 집계나 수록 현황 같은 메타
표를 같은 장에 두고 싶으면 `card_key` 컬럼을 넣지 않으면 된다 — 자동으로 빠진다.

**절 제목이 맥락으로 붙는다.** 행에 테이블 이름이 없어도 `## 주문 상태 코드` 아래의
`PAID`는 "주문 상태 코드의 PAID"로 색인된다. 반대로 말하면 **절 제목이 그 표의 정체를
말해야 한다.** `## 표 1` 같은 제목은 맥락을 버리는 것이다.

**민감 항목에는 🔒를 붙인다.** 그 행은 카드와 색인 양쪽에서 제외된다. LLM에 보내면
안 되는 지식이 책장을 우회로로 삼지 않게 하는 장치다.

## 서술 장을 쓸 때

절 하나에 지식 하나만 담고, **"위반 시 증상"을 함께 쓴다.**

```markdown
## 취소 주문은 매출에 넣지 않는다

(규칙 본문)

**위반 시 증상**: 월 매출이 실제보다 12~18% 높게 나온다. …
```

규칙만 있는 카드보다 "어기면 실제로 이렇게 틀렸다"가 붙은 카드가 모델의 준수율을
올린다. 그리고 그 서술이 임베딩 품질도 올린다 — 서술 카드는 키워드가 안 걸리는 의미
질문을 받아내는 쪽이기 때문이다.

## 흔한 실수

| 실수 | 결과 |
|---|---|
| 장 하나에 전부 몰아넣고 선언 안 함 | 장 통째로 한 카드가 되어 주입 예산을 다 먹고 검색도 뭉개진다 |
| `## 표 1`, `## 목록` 같은 절 제목 | 표 행 카드가 맥락을 잃는다 |
| 행 단위로 뜻이 서지 않는 표에 `row` 선언 | 조각난 카드가 양산된다 |
| 민감 항목에 🔒 누락 | 색인을 통해 LLM 경로로 흘러간다 |
| 한 카드에 지식 여러 개 | 주입 1건에 노이즈가 섞여 고정 청킹과 같아진다 |

## 책을 꽂는 방법

책 하나 = 디렉터리 하나(디렉터리 이름이 book_id). `manifest.yaml`은 선택이며,
없으면 전 locale 대상으로 색인된다.

```
<book_id>/
├── manifest.yaml     # 선택: description, locale
├── 01-해석규칙.md      # card_unit: section
└── 02-지표사전.md      # card_unit: row
```

실제 책은 이 리포에 두지 않는다 — 운영 데이터이므로 책 디렉터리를 컨테이너에 마운트해
등록한다. 이 디렉터리의 `example-book/`은 형식 견본이자 회귀 검증용이다.
