# 주문 데이터 해석 규칙

> 서술 장. 표로 열거되지 않고 **조합해서 읽어야 하는 것**만 담는다.
> 절(`##`) 하나가 카드 하나가 된다.

## 취소 주문은 매출에 넣지 않는다

`orders` 테이블은 취소 주문을 지우지 않고 `status = 'CANCELLED'`로 남긴다. 따라서
매출을 구할 때는 반드시 `status = 'PAID'`로 걸러야 한다. 테이블 전체 합계는
"주문 금액 총액"이지 매출이 아니다.

**위반 시 증상**: 월 매출이 실제보다 12~18% 높게 나온다. 취소율이 높은 달일수록
오차가 커져서, 추세를 보면 "매출이 늘었는데 입금은 그대로"인 모양이 된다.

## 환불은 원주문 날짜로 센다

환불은 별도 행(`status = 'REFUNDED'`)으로 쌓이고 `created_at`은 환불 처리 시각이다.
원주문 날짜는 `original_order_id`를 따라가야 나온다. 일자별 매출에서 환불을 차감할
때 `created_at`을 쓰면 환불이 엉뚱한 날짜에 반영된다.

**위반 시 증상**: 월말에 몰린 환불이 다음 달 매출을 깎는다. 월 경계에서만 숫자가
어긋나므로 일 단위로 보면 이상이 보이지 않는다.

## 결측은 0이 아니다

`discount_amount`가 `NULL`인 것은 "할인 없음"이 아니라 **할인 정보가 적재되지
않았다**는 뜻이다. 할인 없는 주문은 `0`으로 들어온다. `NULL`을 `0`으로 바꿔 합산하면
적재 누락이 "할인 0원"으로 둔갑한다.

**위반 시 증상**: 할인 총액이 실제보다 적게 나오고, 적재 장애가 있던 구간이
"할인 정책이 없던 기간"처럼 보인다.
